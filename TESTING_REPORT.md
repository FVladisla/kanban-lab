# Отчёт по тестированию

**Проект:** Kanban-доска (аналог Jira)
**Дата:** 28.10.2026
**Студент:** Дяченко Дарья 9ИС-375к

## 1. Введение

**Цель:** проверить соответствие Kanban-доски функциональным и нефункциональным требованиям, оценить качество кода и стабильность под нагрузкой.

**Объект тестирования:** клиент-серверное веб-приложение (FastAPI + Vue 3 + PostgreSQL).

**Scope:**
- Аутентификация и авторизация (JWT, роли).
- CRUD проектов, досок, колонок, карточек.
- Перемещение карточек (drag-and-drop), WIP-лимиты.
- Поиск, фильтрация, комментарии, метки, вложения, история.
- Права доступа по ролям.
- Производительность, безопасность.

## 2. Ресурсы

- **Команда:** 1 человек (разработчик + тестировщик).
- **Окружение:** Windows 10, Docker Desktop 4.97, Python 3.12, Node.js 20.
- **Инструменты:** PyTest, httpx, Testcontainers, Playwright, Locust, OWASP ZAP, GitHub Actions.

## 3. Расписание

- Анализ требований и проектирование — 3 дня.
- Разработка — 10 дней.
- Unit- и интеграционные тесты — 2 дня.
- E2E, нагрузочные, security — 2 дня.
- CI/CD и документация — 1 день.

## 4. Критерии начала и окончания

**Начало:** приложение запускается, все эндпоинты доступны через Swagger.
**Окончание:**
- Покрытие кода ≥75% (цель 80%).
- Нет критических багов (High/Critical).
- Все тесты проходят в CI.
- ZAP не находит уязвимостей уровня High.

## 5. Риски

- Нестабильность тестов из-за async event loop — решено через NullPool.
- Playwright не может достучаться до фронтенда из контейнера — решено через `allowedHosts` и `VITE_API_BASE_URL`.
- Долгая установка браузеров в CI — вынесена за пределы основного пайплайна.
